The evaluation endpoint runs a fixed, labelled dataset of 14 synthetic hazard cases through both Ollama and Gemini and returns accuracy and performance metrics for each provider. Because the dataset is versioned and fixed at `data/evaluation/avisos.v1.json`, every run against the same models and configuration produces a comparable result — making it useful for tracking regressions or comparing model upgrades over time.

The evaluation does **not** create notices, does not populate the operational inbox, and does not produce any accepted classifications. Its output is academic, not normative.

## The benchmark dataset

The dataset at `data/evaluation/avisos.v1.json` is deliberately comprehensive for a 14-case set:

- **All 9 categories** are represented by at least one case.
- **Ambiguity cases** — inputs where the correct category is genuinely unclear — test the model's ability to pick the most defensible label rather than invent certainty.
- **Insufficient-information cases** — inputs with too little detail to classify reliably.
- **Demographic-variant pairs** — pairs of cases that differ only in a demographic attribute (e.g., worker age) and must produce the **same** expected label. These test that urgency and category are not influenced by irrelevant personal characteristics.

Each case in the dataset carries an `id`, `text`, optional `location`, `expected_category`, `expected_urgency`, `expected_department`, `tags`, and optionally `bias_pair_id` and `bias_attribute` to link bias-test pairs together.

## Running the evaluation

No request body is required. Both providers are invoked automatically.

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/evaluations | python3 -m json.tool
```

Or with PowerShell:

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/v1/evaluations
```

<Note>
  The evaluation calls both providers for all 14 cases in sequence. With Ollama running locally this may take 30–90 seconds depending on your hardware. Gemini requires `EXTERNAL_API_KEY` in `.env`; without it the external provider will return errors for every case and its metrics will reflect those failures.
</Note>

## EvaluationReport structure

The response is an `EvaluationReport` object.

<ResponseField name="dataset_version" type="string">
  The version string read from the dataset file (e.g. `"avisos.v1"`). Use this to confirm you are reading results from the expected dataset.
</ResponseField>

<ResponseField name="generated_at" type="datetime">
  ISO 8601 timestamp of when this evaluation run was executed.
</ResponseField>

<ResponseField name="disclaimer" type="string">
  The disclaimer text embedded in the dataset file, carried through to the response. Confirms that results are synthetic and not a professional benchmark.
</ResponseField>

<ResponseField name="summaries" type="array">
  An array of two `ProviderEvaluationSummary` objects — one for each provider.
</ResponseField>

### ProviderEvaluationSummary fields

Each entry in `summaries` describes one provider's performance across all 14 cases.

<ResponseField name="provider" type="string">
  `local` (Ollama) or `external` (Gemini).
</ResponseField>

<ResponseField name="cases" type="integer">
  Total number of cases run (14 for a full run).
</ResponseField>

<ResponseField name="category_accuracy" type="float | null">
  Proportion of cases where the predicted category matched the expected label. `null` if no successful results were produced.
</ResponseField>

<ResponseField name="urgency_accuracy" type="float | null">
  Proportion of cases where the predicted urgency matched the expected label.
</ResponseField>

<ResponseField name="department_accuracy" type="float | null">
  Proportion of cases where the predicted department matched the expected label.
</ResponseField>

<ResponseField name="json_valid_rate" type="float | null">
  Proportion of responses that were valid, parseable JSON conforming to the `TriageResult` contract — including any repair attempts.
</ResponseField>

<ResponseField name="mean_latency_ms" type="float | null">
  Mean wall-clock latency in milliseconds across all cases.
</ResponseField>

<ResponseField name="mean_api_cost" type="decimal | null">
  Mean estimated API cost per case. `null` if token counts were unavailable or the pricing reference did not match the model in use.
</ResponseField>

<ResponseField name="api_cost_currency" type="string | null">
  ISO 4217 currency code for `mean_api_cost` (e.g. `"USD"`). `null` if cost could not be computed.
</ResponseField>

<ResponseField name="reviewed_notices" type="integer">
  Number of evaluation observations that were subsequently reviewed by a human (useful when the evaluation dataset is also run through the operational inbox).
</ResponseField>

<ResponseField name="human_correction_rate" type="float | null">
  Proportion of reviewed observations where the human technician changed at least one classification field. `null` if no human reviews exist for this evaluation run.
</ResponseField>

## Bias pair validation

The dataset includes cases grouped by `bias_pair_id`. Within each pair the hazard description is identical except for a single demographic attribute (`bias_attribute`, e.g. `"edad"`). Both cases in the pair carry the same `expected_category`, `expected_urgency`, and `expected_department`. If the model produces different classifications for the two members of a pair, that discrepancy is visible in the per-case accuracy breakdown and is considered a failure for those cases — the expected labels are identical.

The system prompt instructs the model to ignore demographic attributes that are irrelevant to the physical hazard. The benchmark dataset makes this testable and reproducible.

## Historical aggregate vs. per-run evaluation

<CardGroup cols={2}>

<Card title="POST /api/v1/evaluations" icon="flask" href="/api/evaluations">
  **Per-run benchmark.** Runs the fixed 14-case dataset right now and returns accuracy and performance for this single execution. Does not persist anything to the notice database.
</Card>

<Card title="GET /api/v1/metrics/summary" icon="chart-bar" href="/api/metrics">
  **Historical aggregate.** Aggregates all triage executions and comparison runs that have been persisted to SQLite over time. Returns acceptance rate, correction rate, rejection rate, and per-provider metrics including human agreement rate, token totals, and cost totals.
</Card>

</CardGroup>

Use `POST /api/v1/evaluations` when you want a controlled comparison of the two models on the same fixed inputs. Use `GET /api/v1/metrics/summary` when you want to see how the system is performing in day-to-day operational use.

## Running from the React UI

The React comparison view includes an **Execute benchmark** button that calls `POST /api/v1/evaluations` on demand and displays the results inline — showing category, urgency, and department accuracy, JSON valid rate, mean latency, and mean cost for both providers, without leaving the browser.

<Note>
  Results produced by this evaluation are **academic and not normative**. The dataset is synthetic and didactic; it does not represent a professional benchmark, a regulatory assessment, or a certified safety evaluation. A safety technician must always review AI proposals before any classification is applied operationally.
</Note>
